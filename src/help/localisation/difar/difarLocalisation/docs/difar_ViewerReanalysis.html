DIFAR Localisation

Reanalysis in Viewer mode (PAMGuard version 2.03 or later)

From PAMGuard version 2.03, DIFAR data can be reanalysed in Viewer mode. The operator can mark new DIFAR clips from the raw audio, save and delete DIFAR clips, choose which DIFAR clips form a triangulation, edit sonobuoys, and match every DIFAR clip again in a single batch task. Each change is written to the binary files and the database immediately.

Reanalysis works in much the same way as the DIFAR module in Normal mode. The queue, the DIFARGram and the triangulation match selector behave as they do in Normal mode. This page describes the differences in Viewer mode.

Terms used on this page

DIFAR clip: a short section of audio containing one call, recorded on one sonobuoy.

Bearing: the direction to the sound source, measured from one DIFAR clip.

Match: a set of DIFAR clips on different sonobuoys that are believed to contain the same call.

Triangulation: a saved match, with the location where its bearings cross and the error of that location. See Triangulation.

Requirements

Reanalysis requires a DIFAR dataset recorded with PAMGuard. Such a dataset consists of:

  1. a PAMGuard database, which Viewer mode requires in any case;
  2. audio files whose names contain their start times in a format that PAMGuard can read;
  3. a binary store module and its folder.

Sonobuoy deployments and the vessel track. The database must contain the sonobuoy deployments and the vessel's GPS track. The GPS track is also required for vessel calibration of the sonobuoy compasses. PAMGuard records both during a survey, so a DIFAR dataset recorded with PAMGuard meets this requirement. For data recorded with other systems, the sonobuoy deployments and the vessel track must be imported first, as described in the post-processing tutorial.

Audio files. Audio files are required to mark new DIFAR clips. Set the audio folder in the offline file settings of the Sound Acquisition module, or start PAMGuard with -wavfilefolder (see Opening a dataset). Saved DIFAR clips contain their own audio, so they can be viewed and deleted without the audio files.

DIFAR binary files at version 3. Reanalysis writes DIFAR binary files at version 3. Datasets recorded before PAMGuard version 2.03 must be upgraded to version 3 before DIFAR clips can be saved or deleted. Until then, they can be viewed but not changed.

Opening a dataset

Open the dataset's own database. PAMGuard offers the most recently used database by default. If a copy or a subset of a dataset is opened with the database of another dataset, its DIFAR clips are paired with the wrong database rows and triangulations.

Command line arguments. The startup dialogs can be skipped by passing the files as program arguments:

-v -databasefile <database>.sqlite3 -binaryfolder <binary folder> -wavfilefolder <audio folder>

The database name must end in .sqlite3; otherwise it is ignored and the dialog appears. A binary folder that does not exist is created empty, so check the path carefully. The argument -wavfilefolder is case-sensitive.

Map. The map draws sonobuoys as their own data ("Sonobuoy Positions" in the key), built from the sonobuoy records in the database; they are not stored separately. Enable them on the map, and tick "all data" in their plot options. Otherwise the map draws only the sonobuoy records within the time window of the view, and a sonobuoy deployed before the start of the view is not drawn.

Buoy manager. The time window controls for the buoy manager are at its bottom edge, below the calibrations.

Upgrading an older dataset

Run Upgrade old DIFAR files to version 3 from the DIFAR offline tasks (Settings > DIFAR Localisation > Offline tasks), with the data choice set to All Data. The task refuses any other data choice, because matching must be able to find DIFAR clips anywhere in the dataset. The task:

  1. Checks for DIFAR clips that share a UID. Older datasets can contain repeated UIDs as a result of software faults or crashes, and these must be resolved before the upgrade. A confirmation dialog states that the repeated UIDs will be renumbered.
  2. Copies every DIFAR binary file and the database into a new, dated backup folder beside the binary folder. The task stops if either copy fails.
  3. Rewrites every DIFAR clip to a version 3 binary file, and ensures that the DIFAR Localisation table of the database contains one row for each DIFAR clip.
  4. Matches every DIFAR clip again, creating new triangulations.

Triangulations made by earlier versions of PAMGuard are kept only in the backup, as a record of the original analysis.

Marking new DIFAR clips

Draw a box around a call on the spectrogram, as in Normal mode. The audio for the DIFAR clip is read from the audio files, in the same way that annotations read audio in Viewer mode. If the audio cannot be found, no DIFAR clip is made and a warning is shown instead. The usual cause of this warning is a mark within a gap between audio files.

Gaps between audio files. PAMGuard stops reading audio at a gap of more than one second. A spectrogram that starts shortly before a gap may therefore remain blank after the gap, even though audio follows. Scroll forward until the spectrogram starts after the gap.

Assign Classification. The "Assign Classification" checkbox in the side panel works as it does in Normal mode. When it is checked, a new DIFAR clip takes the selected classification as soon as it is marked, and is shown in the queue at the sample rate for that classification. Changing the classification of a queued DIFAR clip redraws it at the new sample rate.

The queue and saved DIFAR clips

New DIFAR clips wait in the Queue strip, as in Normal mode. DIFAR clips that have already been saved are shown in the Saved strip.

A saved DIFAR clip can be opened in the DIFARGram to inspect its bearing, but it cannot be changed or saved again. Its classification buttons (the species buttons, Vessel and Other) are disabled. To change a saved DIFAR clip, delete it and mark the call again.

Saving a DIFAR clip

Process a queued DIFAR clip and select its bearing in the DIFARGram, as in Normal mode. The Triangulation match selector below the DIFARGram lists the matches with DIFAR clips on other sonobuoys, with the best match selected. To use another match, select it in the list. To save the DIFAR clip without a triangulation, press Clear match. Saving a DIFAR clip with a match creates its triangulation.

Auto save works in Viewer mode for new DIFAR clips, as set in the Automation settings. Clicking in the DIFARGram, deleting the DIFAR clip, or saving it manually stops the countdown. A saved DIFAR clip that is opened again is never saved automatically.

Deleting a DIFAR clip

Press Delete on a saved DIFAR clip, in the Saved strip or in the DIFARGram. PAMGuard asks for confirmation first, naming the DIFAR clip and stating what will happen to its triangulation. A triangulation left with two or more DIFAR clips is recalculated from them. A triangulation left with one DIFAR clip is deleted. The DIFAR clip is removed from its binary file and from the database immediately.

Editing sonobuoys

A change to the location, heading or times of a sonobuoy in the buoy manager can change which DIFAR clips match. After a sonobuoy is edited, PAMGuard therefore matches the DIFAR clips again over the period of that sonobuoy. The triangulations, and the database rows of the DIFAR clips, take the new values for the sonobuoy.

Matching all DIFAR clips again

Run Rematch clips from the DIFAR offline tasks to match every DIFAR clip in a period again. Use it after changing the Localisation settings, or to rebuild the triangulations after many edits. The settings of the task determine whether triangulations chosen by the operator are kept, and recalculated from their DIFAR clips, or replaced. By default they are kept.

DIFAR clips are matched in time order, one file at a time, in the same way that an operator works through the queue. Each DIFAR clip takes its best match among the DIFAR clips that are not already part of a triangulation, so the result can depend on the order.

When the task finishes, the console shows a summary: the number of DIFAR clips matched, the number of triangulations made, the number of triangulations on a sonobuoy or with a small crossing angle, and the number of DIFAR clips that had no sonobuoy location. When Time delays by correlation is selected, it also shows how many pairs of DIFAR clips were correlated, how many passed the threshold and their mean peak height, and how many had no correlation peak above the threshold.

The task also writes the residuals of every triangulation it made to a CSV file beside the database, named after the database, for example survey_triangulation_residuals_20261005_061500.csv. There is one row for each arrival time difference in each triangulation, giving the two sonobuoys, their separation and the travel time between them, the measured and predicted arrival time differences and their difference (the residual), whether it was measured by correlation, the hours each sonobuoy had been deployed, and the bearing residual of each DIFAR clip. When correlation is on, each row also gives the DIFAR clip the others were correlated with (the seed), and for each of its two DIFAR clips how the correlation went: CORRELATED if the best peak passed the threshold, BELOW_THRESHOLD if it did not, NOT_COMPARABLE if the DIFAR clips could not be correlated, or SEED, with the height of the best peak. The heights show whether the threshold suits the detector that made the DIFAR clips. Each row also gives the location of the triangulation and of both sonobuoys, so the residuals can be compared with what errors in the sonobuoy positions would produce. Hours deployed are counted from the first record of each sonobuoy in the sonobuoy history, so they are only meaningful if those records carry the real deployment times. Plotted against separation and against time since deployment, the residuals show how large the timing errors are, and whether drifting sonobuoys contribute to them. The upgrade, which runs the same matching, writes the file too.

Known limitations

New bearings appear late on the map. The map draws data up to the left edge of the spectrogram, so a DIFAR clip saved on screen appears on the map only once it has scrolled off the spectrogram. "Display all selected data" draws the whole loaded period instead.

Matching across file boundaries. Rematch clips and the upgrade load one binary file at a time. A DIFAR clip within a few seconds of the start or end of a file therefore cannot be matched with DIFAR clips in the neighbouring file. This may be addressed in a future version. DIFAR clips saved manually are not affected.

Saved DIFAR clips cannot be edited. Delete the DIFAR clip and mark the call again.
